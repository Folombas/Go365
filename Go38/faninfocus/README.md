## 🎯 Суть модуля: Fan-In как метафора самоконтроля

Программа демонстрирует паттерн **Fan-In** через борьбу с внутренними отвлечениями:

- **Несколько источников мыслей** → **Несколько каналов-горутин**
- **Объединение в один поток** → **Функция fanIn**
- **Централизованная обработка** → **Сознательное принятие решений**

### Реальные аналогии:
- **Трейдинг:** Сбор данных с разных бирж в единый поток
- **Мониторинг:** Агрегация логов с нескольких серверов
- **Чат-бот:** Объединение сообщений из разных каналов

## 🧩 Что такое Fan-In Pattern?

### Определение:
**Fan-In** — паттерн конкурентности, который объединяет несколько входных каналов в один выходной канал для централизованной обработки данных.

### Зачем нужен?
1. **Упрощение кода** — один обработчик вместо N
2. **Контроль потока** — управление скоростью обработки
3. **Масштабируемость** — легко добавить новые источники
4. **Чистая архитектура** — разделение ответственности

### Реализация в Go:
```go
func fanIn(sources []chan Data) <-chan Data {
    combined := make(chan Data)
    var wg sync.WaitGroup

    for _, source := range sources {
        wg.Add(1)
        go func(s <-chan Data) {
            defer wg.Done()
            for item := range s {
                combined <- item
            }
        }(source)
    }

    go func() {
        wg.Wait()
        close(combined)
    }()

    return combined
}
